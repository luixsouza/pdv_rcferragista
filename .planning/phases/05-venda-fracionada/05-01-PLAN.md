<objective>
Create a single source of truth for fractional-quantity behavior. Every page that lets the operator type a quantity (POS, Quotes) or a stock value (Products) must agree on which units accept decimals and what input step to use. Centralizing this in `src/lib/units.ts` prevents the three pages from drifting.

Purpose: The locked decision is "conforme a unidade" — fractional behavior is derived from the product's `unit` string, not a per-product flag. This plan encodes that decision once.
Output: `src/lib/units.ts` with pure, dependency-free helper functions.
</objective>

    2. `isFractionalUnit(unit: string): boolean` — returns true when `unit` (lowercased, trimmed, undefined-safe) is in `FRACTIONAL_UNITS`. Discrete units (`un`, `cx`, `pc`, `par`, `jg`, `rl`, `mil`) and any unknown/empty string return false.

    3. `quantityStep(unit: string): number` — returns the input/`+`/`-` step for the unit: fractional units return `0.5` (Claude's Discretion per CONTEXT — choose 0.5 so the +/- buttons move in half-units, matching how pipe/rope is commonly sold; document the choice in a comment); discrete units return `1`.

    4. `parseQuantity(raw: string): number` — normalizes a raw input string to a number. Replace a single decimal comma with a dot before `parseFloat` (pt-BR locale, Claude's Discretion per CONTEXT). Return `NaN` for unparseable input so callers can guard with `isNaN` (matching the existing `isNaN` guard pattern in POS).

    5. `clampQuantityForUnit(quantity: number, unit: string): number` — if the unit is discrete, round the quantity to the nearest integer (prevents 1.5 un); if fractional, return the quantity unchanged. This enforces "não permitir fração em un/cx".

    Pure module: no React, no imports from pages, no storage access. Use named exports (lib convention). Add `@param`/`@returns` JSDoc on each function, mirroring cardFees.ts comment style.
